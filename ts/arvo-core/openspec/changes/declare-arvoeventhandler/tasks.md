## 1. Probes before types

- [x] 1.1 Probe that a mapped type over `keyof M & ArvoSemanticVersion` rejects a handler declaring fewer versions than the contract, against a real `ArvoContract` built inline — two versions declared, one executor given, expect a compile error. Repeat with the contract's versions map held in an annotated `const` to confirm the widening trap `ArvoContract`'s own TSDoc describes degrades the check rather than breaking it.
- [x] 1.2 Probe that `Partial<T>` over a field typed `number | null` yields `number | null | undefined` and that TypeScript distinguishes an absent key from an explicit `undefined` only at the value level, not at the key level. This decides that resolution keys off `value === undefined` rather than `in`.
- [x] 1.3 Probe that `VersionedArvoContract` exposes `uri`, `type`, `version`, `outputs` and `error.type` off a value typed only as `VersionedArvoContract`, so the collision and duplicate-service rules can read them without a cast.
- [x] 1.4 Probe the generics the context sketch in `proposal.md` depends on, since every one of them has to be inferable from a single `new ArvoEventHandler({...})` call and none can be annotated by hand. Four things, and each has been wrong in a draft: that the services map infers as written rather than widening to `Record<string, VersionedArvoContract>`; that `StateSchemaOf<VD, V>` reads a version's own `state` back out of the same object literal that declares it; that a version written as the executor alone infers as stateless; that `H` and `D` infer off the `types` witness field and fall to `Record<string, never>` when it is omitted; and that a union of intersections narrows on `entry` where an intersection carrying a union does not — the collapse the factories change already hit with `Omit<A & (B | C), K>`. Record what compiles, because §2.2 is written against the answer.

## 1a. The execution state and the fault

Both were separate changes until the context needed them. Tests first, as every step from here.

- [x] 1a.1 Add `src/ArvoEventHandler/fault/types.ts`: the `fault_kind` vocabulary, the retry block, and what a fault is built from. No field optional; where there is nothing to say, say `null`.
- [x] 1a.2 Add `src/ArvoEventHandler/fault/index.ts`: `ArvoHandlerFault`, an `Error` so it can be thrown and caught as one, frozen, with a `toJSON` because whatever runs the handler may store it.
- [x] 1a.3 Add `src/ArvoEventHandler/state/types.ts`: what an `ArvoExecutionState` is built from, the lifecycle vocabulary, and the shapes of what it holds. No field optional. Three generics: `TDataSchema` typing `data`, `TInitEvent` and `TTriggeringEvent` typing the two events it holds. The schema is carried nowhere.
- [x] 1a.4 Add `src/ArvoEventHandler/state/validator.ts`, checking the whole envelope: identifiers are strings, `depth` and `casVersion` non-negative integers, `lifecycle` one of six, `recordFormatVersion` a semantic version, both events events. Shape and domain only; whether a record agrees with the contract it names is the gate's.
- [x] 1a.4a Add `src/ArvoEventHandler/state/errors.ts` with `ArvoExecutionStateValidationError`, following `ArvoEventValidationError` and carrying `ErrorIssue[]`.
- [x] 1a.4b Add `src/ArvoEventHandler/state/index.ts`: `ArvoExecutionState`, frozen, validating in its constructor, with `build`/`tryBuild` statics for rebuilding one from something that is not yet a record.
- [x] 1a.4c Add `src/ArvoEventHandler/state/utils.ts` with `tryMutateState(current, next)` and `mutateState` as the thin unwrap over it, taking a partial of the record's fields and generic in the record so what comes back is the same kind. It carries every field not named across and checks nothing beyond the envelope the constructor always checks: data is the caller's to check, because the schema is the caller's to hold. Split `ArvoExecutionStateFields` out of `ArvoExecutionStateParam` so the partial can be typed by the values a record holds rather than by a schema it does not carry.
- [x] 1a.4d Remove the delivered event and the init event from the context: both are on the record, and two ways to read one value is two things to keep in step. `ctx.state` becomes the record itself, `setState({ data })` mints the next one through `mutateState`, and the data schema arrives as its own field because a record does not carry one. `ArvoStateOnArrival` goes with them — the record's own data already says what was there.
- [x] 1a.5 Add `src/ArvoEventHandler/state/serializer/` as `index.ts`, `errors.ts` and `types.ts`: `ArvoExecutionStateSerializer`, bound to one version's data schema at construction, with a `tryX` pair each way and its own error carrying the original cause. The events a record holds are written in the event's own format through `ArvoEventSerializer` in `arvoevent` mode, hard-coded rather than offered as a choice — a stored record is read by whatever reads it next, so its format cannot depend on how its writer was configured. Asynchronous, because `ArvoEventSerializer` is; the earlier note that it would be synchronous assumed nothing was awaited, which reuse settles.
- [x] 1a.6 Reading back: parse the string, restore every stored event through `ArvoEvent.tryParse`, rebuild the collection as a map, and hand the rest to `ArvoExecutionState.tryBuild`. The serializer checks nothing the record checks itself, and reports rather than returning anything half restored.
- [ ] 1a.7 Probe that a version declaring no schema must be given a loose one: `z.object({})` strips every undeclared key, so a closed default would silently empty an execution's data on every write. Pin both behaviours.

- [x] 1a.4e Add `src/ArvoEventHandler/context/factory.ts` with `tryCreateInitArvoExecutionContext` and `tryCreateFollowupArvoExecutionContext`, and their throwing halves. Two entry points rather than one taking a nullable row: opening an execution and resuming one need different inputs, and once separate neither can be handed the other's. Opening is synchronous and derives what it can from the event and the contracts; the identity and the contracts snapshot are supplied, never derived, because whatever looked for a record already knew which execution it wanted. Resuming reads the row, leaves the event log and what is awaited exactly as stored, replaces only the triggering event, and refuses a record naming a different execution.
- [x] 1a.4f Add `src/ArvoEventHandler/helpers/defaults.ts`: the loose data schema a version declaring none is given, the record format version, and the lifecycle and revision an execution opens at. The only place in the package that spells any of them.
- [x] 1a.4g Drop `TArvoEntryKind` from the context. The delivered event is a plain union and narrowing happens on `type`, which the collision rule already guarantees is unique, so the generic bought nothing the event itself did not.

- [x] 1a.4i Build the abandonment pair where a write is refused. `ArvoHandlerFault` carries the record itself rather than a flattened one, and `ArvoExecutionState.toJSON` becomes the single definition of a record's plain shape — read by the fault and by the serializer, so nothing spells it twice. The event is addressed to the caller per ADR-006's completion column, and comes back `null` where it could not be built, so a fault that must be raised is never lost to a second failure while raising it. The builder is `#`-private: an executor holds the context, and ADR-006 forbids an executor constructing the handler error event. It moves to a shared function when the handler raises faults of its own.

- [x] 1a.4j Add `tryExportFinalState`/`exportFinalState` to the context: what an execution finished as, written out for whatever stores it. It advances the revision itself, which is why there is no method to do so by hand — a record committed at the revision it was read at cannot be told apart from one nobody wrote, so a store comparing revisions would accept a concurrent write over the top, and making it part of writing the record out is what stops that being forgettable. It refuses empty data outright. The context never sees an absent schema — the factory resolves a version that declared none to the loose one before a context exists — so nothing inside it compares against that default to work out which rules apply. A version remembering nothing in particular writes `{}` and says so. It reads the context rather than changing it, so calling it twice gives the same string. The abandonment record advances its revision for the same reason.

- [x] 1a.4k Add `ctx.fault(...)`, public and used by the context itself. It builds rather than throws, so a caller decides where the fault leaves from. Everything about the delivery is filled in from the record; a caller says only the kind, what went wrong, optionally what underlies it, the checks that failed, and whether another attempt is due. The abandonment pair is built with it, and nothing is published or committed.
- [x] 1a.4l `exportFinalState` throws a fault rather than reporting, and has no `try` twin. Empty data is `state_schema_rejected`; a record that will not write out is `state_not_serializable`. Both kinds are already in ADR-008's vocabulary, so nothing was invented for them.

**Deferred, and named so it is not lost:** `retry` on `ctx.fault` is the whole `ArvoFaultRetry` block today, because the version's resolved options are not on the context yet and nothing here can work out when the next attempt is due. Once they are, this becomes a boolean and the context does the arithmetic.
