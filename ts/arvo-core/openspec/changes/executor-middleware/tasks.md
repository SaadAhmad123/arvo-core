## 6. Adversarial — every way a layer author can get it wrong

Each of these is a test that passes only because the implementation refuses, contains, or ignores the misbehaviour. None is a representative sample; the bar is `project.md` — *Testing*: bespoke code is held higher than code that delegates. Add `tests/ArvoEventHandler/middleware/` with one spec file per heading.

- [x] 6.1 **Misbehaving before parts.** Throws a string, a number, `null`, `undefined`, a plain object, a fault belonging to another execution (refused as today), a fault with `retryable: true` and with `false`; throws synchronously versus rejects; never resolves (run clock); resolves after the clock already fired (nothing it did afterwards is acted on); writes state the schema rejects (`state_schema_rejected`, as from the executor); cancels and the executor then answers / does not answer; builds an event and returns it (ignored); mutates the context's frozen members (throws, in strict mode); re-enters `setMiddleware` recursively from inside a getter on the value it stores.
- [x] 6.2 **Misbehaving after parts.** Throws every kind of value above; raises a fault — the result stands, the fault is on the span, not in the response; mutates the frozen emission array (throws, recorded, discarded); mutates an event's fields (frozen — throws); returns an event, a promise of events, `false` (ignored); never resolves (clock cuts it; result stands; remaining afters skipped); resolves after the cut (nothing recorded); calls `setState` — permitted in the seat, but the record was already decided from the executor's return: assert the write is **not** in the produced record and is recorded as a discarded late write, or decide and document; calls `setMiddleware` (allowed; useless; harmless); calls `cancel` after the executor returned (the lifecycle the executor's return decided stands — assert and document).
- [x] 6.3 **Identifiers.** A factory returning a different id on each call (allowed — it is one instance per execution); a factory returning the same instance every call (then it is a shared instance and the per-delivery rule applies — document);  Empty string; whitespace; very long; unicode; two ids differing only by case are distinct; the same layer *instance* supplied twice (duplicate id → `middleware_conflict`); a supplied id equal to a declared id; declared duplicates alongside other declaration errors are all reported together; an id that is not a string at runtime (JavaScript caller) — refused at build with an issue, and at execution with a fault.
- [x] 6.4 **Middleware data keys.** `__proto__`, `constructor`, `prototype`, `toString`, `hasOwnProperty` as keys — written and read back without touching the prototype, no pollution of `Object.prototype`; empty-string key; a key written with `undefined` as the value counts as present (second write conflicts); a value that is a function, a class instance, a cyclic object, a frozen object — stored by reference, read back identical, never serialized; a layer that stores the context itself as a value (no leak into the record); the read copy is frozen but the stored value is not deep-frozen (a layer may mutate its own stored object — documented, asserted).
- [x] 6.5 **Order and shape.** Zero layers, one, two, fifty, five hundred (order exact, no stack growth beyond linear); only declared; only supplied; a layer with neither part among others; the same instance declared on two handlers (fine — holds nothing); interleaving verified by a shared log with monotonic timestamps; a before part that takes measurably long shifts the clock seen by the executor's `timeRemaining`.
- [x] 6.6 **Clocks at every boundary.** Clock fires during before #1, during before #N, during the executor, between the executor returning and the first after, during after #1, during after #N, after all afters finished (no effect); `runTimeout: null` with slow afters (nothing cuts them); execution clock crossed by a slow before (refused at return for time — the executor never ran, so the broader verdict wins as ADR-009 says); execution clock crossed only by a slow after (not refused).
- [x] 6.7 **The protocol around the chain is untouched.** Idempotency keys identical with and without layers; `event_ids` and `in_flight_event_map` identical; `cas_version` identical; the record exported is byte-identical for an execution whose layers only read; a partial collection enters no layer; a discarded duplicate enters no layer; a gate refusal enters no layer; a dependency that fails to open enters no layer; `close()` on the dependency still runs after a before part that threw.
- [x] 6.8 **Concurrency.** A factory-made layer holding state on `this` across 100 concurrent executions — no cross-talk, one instance each; one *shared* layer instance across 100 concurrent executions of one handler, each writing middleware data — no cross-talk; the same across the worker-thread scenario (`scenarios/threads.spec.ts`); a layer that stores per-delivery state on `this` is shown to leak under concurrency — as a documented negative test proving the rule in the TSDoc is real.

## 7. The sandbox — all three mechanisms, with failures injected

The sandbox is a proving ground, not authority: what it finds comes back here as a test or an ADR question, never as a rule by itself.

- [x] 7.1 Add layers to the distributed handlers under `ts/sandbox/src/distributed/handler/`: a tenant layer (writes middleware data every executor requires), a duration layer (made per execution, holding its start time on itself). The purity check still passes — layers import no framework. **Deviation:** no layer writes state in the sandbox. Several executors write state in the function form, reading what is there, so a layer's write would change records the cross-mechanism replay compares; writing state from a before part is covered in the package (`middleware/execution.spec.ts`, `before.spec.ts`).
- [x] 7.2 Each of the three mechanisms supplies one layer per execution (`middleware` on `tryExecute`), so supplied-outside-declared is exercised under Temporal, DBOS and the plain loop.
- [x] 7.3 A failure-injection layer, switchable per run: throws in before on the Nth delivery; faults retryable in before; throws in after; hangs in after past the run clock; writes a duplicate key; is supplied with a duplicate id. Each run asserts the protocol's outcome under each mechanism — retried where retryable, dead-lettered where not, result standing where the after failed — and that §12's cross-mechanism replay still agrees byte for byte.
- [x] 7.4 Soak: the §scale scenario with layers on every handler for the full run; no growth in span count per delivery; no leak across concurrent deliveries; the tape replays identically.
- [x] 7.5 Anything the sandbox turns up that the package tests did not: write the package test first, then fix.
